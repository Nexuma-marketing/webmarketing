# Fix Implemented (component reused, expand/collapse behavior)

**Where the bug lived:** the "Recommended for You" grid on `/dashboard/services` ([src/app/(dashboard)/dashboard/services/page.tsx:1008-1083](<src/app/(dashboard)/dashboard/services/page.tsx#L1008-L1083>)) renders every row from the `services` table that targets the viewer's role. For `pymes` users, that includes three rows seeded in `supabase/migration_v11_steve_4_29_fixes.sql:253-264` — `Plan: PYMES — Rescue/Growth/Scale` — each with only a `name`, a one-line `description`, and a `price`; no `features` array was ever seeded for them. The card's existing feature-list block (`pickFeatures(service)`) correctly renders nothing when a service has no features, so these three cards silently showed name + description + price + purchase button only, while the canonical full checklist for each plan (used for the customer's *own* recommended plan) lives in `PYMES_PLANS` ([src/lib/constants.ts:149-220](src/lib/constants.ts#L149-L220)) and is rendered by `PymesPlanCard` ([src/components/dashboard/pymes-plan-card.tsx:63-70](src/components/dashboard/pymes-plan-card.tsx#L63-L70)) — a completely separate data path the "Recommended for You" grid never reads from.

**Fix:**
1. Added a small matcher, `getPymesPlanKey(name)`, next to the existing `pickFeatures`/`formatServicePrice` helpers ([:408-419](<src/app/(dashboard)/dashboard/services/page.tsx#L408-L419>)). It recognizes the three `Plan: PYMES — …` service names and returns the corresponding `PYMES_PLANS` key (`"rescue" | "growth" | "scale" | null`), so only those three cards are affected — every other service card (photography, virtual tours, owner/investor plans, etc.) is untouched.
2. Inside the `relevantServices.map()` card body ([:1046-1066](<src/app/(dashboard)/dashboard/services/page.tsx#L1046-L1066>)), when a card matches a PYME plan, it now renders a `<details>`/`<summary>` "View Details" accordion, closed by default (no `open` attribute), containing the plan's full `PYMES_PLANS[...].features` checklist.
3. **Checkmark component reused exactly, not duplicated:** the `<ul>`/`<li>`/`CheckCircle2` markup and classes inside the accordion (`space-y-1.5` list, `flex items-start gap-2 text-sm` items, `mt-0.5 h-4 w-4 shrink-0 ${color}` icon) are the same shape as `PymesPlanCard`'s existing feature list ([pymes-plan-card.tsx:63-70](src/components/dashboard/pymes-plan-card.tsx#L63-L70)), and use the plan's own `color` from `PYMES_PLANS` so Rescue/Growth/Scale keep their distinct accent color, matching what's shown for the user's own recommended plan.
4. **Expand/collapse mechanism reused, not reinvented:** rather than adding new client-side state, the change reuses this same file's existing `<details className="group">` + `group-open:hidden`/`hidden group-open:inline` accordion idiom, already used twice in this file (owner "Property add-on services" groups, and the PYME "Explore our property marketing plans" opt-in, [:1067-1112](<src/app/(dashboard)/dashboard/services/page.tsx#L1067-L1112>)). Being native `<details>`, each card's accordion opens/closes independently with no JavaScript and no new client component, keeping this a server component exactly as it already was — collapsed by default, and clicking one card's "View Details" never affects the other two.

# Expected Result

A `pymes`-role customer viewing `/dashboard/services` now sees, on each of the three "Recommended for You" plan cards (Rescue/Growth/Scale), a "View Details" toggle beneath the price. Collapsed by default, all three cards keep the section compact; clicking one expands only that card to show the same feature checklist (with the same checkmark styling and plan accent color) already shown for the customer's own recommended plan elsewhere on the page — making it possible to compare all three plans' full inclusions before deciding whether to switch. Every other card in "Recommended for You," the "Other Available Services" section, pricing, descriptions, and purchase-button behavior are unchanged, and Property Owner/Investor/Tenant flows were not touched (this grid's role-based filtering already excluded them from seeing these three plan cards).
